# Round 2 — POLICE `ba064a4` rework (P1 commit-window race, P2 pin extraction)

## P1 — `apps/web/src/app/search/page.tsx`: commit-window race (A's data under B)

**Finding.** The render-phase reset (round 1) runs BEFORE the passive effect that
invalidates the in-flight run id, so a stale A resolution landing between B's
render and B's passive effect still passed the run-id fence and painted A's
private result (or error) under B. Reproduced by POLICE in a real browser
(`/tmp/police-ba064a4-browser-matrix/output.html`): candidate
`privateVisible: true` / `privateErrorVisible: true`; parent `2362eba` clean.

**Fix — the workspace fence is now atomic (identity fence).** A published value
carries the workspace it belongs to, and visibility is decided by the ACTIVE
workspace, not by when the value happened to land:

- `type Scoped<T> = { workspaceId: string; value: T }`; `response`, `error` and
  `selected` hold a `Scoped` value.
- The publication stamps the workspace the REQUEST was made for — not the
  workspace that is active when the value lands:
  `setResponse({ workspaceId, value: result })` / `setError({ workspaceId, value: msg })`.
- Visibility is filtered by the active workspace:
  `visibleResponse` / `visibleError` / `visibleSelected`
  (`x.workspaceId === scopeId`).
- The run-id fence (`runIdRef.current !== thisRun`) still drops a superseded run
  before it writes anything; the identity fence is what makes the guarantee
  hold in the commit window (it does not depend on effect ordering).

The 5 original wiring assertions are preserved (all still pass); the only
adaptation is that the empty-query error is now published scoped, so the
assertion accepts both shapes. Three assertions were **added** for the identity
fence (publication carries the workspace; visibility is filtered by it).

# Round 3 — POLICE `157feb4` rework (F1 active-workspace invalidation, F2 complete pin parsing)

## F1 [P2 T-IMP-003] — a request started for the ACTIVE workspace was superseded

**Finding (POLICE `157feb4`).** The passive-effect invalidation
(`runIdRef.current += 1` on `[activeId]`) is unconditional: a request started
for the NEW workspace during that workspace's own layout commit (before the
passive effect runs) was superseded by the effect that follows it. Reproduced
by POLICE in a real browser (`/tmp/police-157feb4-browser-matrix/report.json`):
`newBVisible: false`, `bErrorVisible: false`, `loadingVisible: true` — the UI
stuck on "Searching…". Trace:
`layout:B → request:B → submitted B in B layout → passive:B → settle B after passive`.

**Fix — invalidate OLD-workspace work only.** The run now remembers the
workspace it belongs to (`lastRunRef`), and the effect only supersedes work
that does NOT belong to the workspace that is already active:

```tsx
const lastRun = lastRunRef.current;
if (lastRun && lastRun.workspaceId !== (activeId ?? "")) {
  runIdRef.current += 1;
}
```

A request for the active workspace (submitted in its own commit window) is
preserved; old-workspace work is still superseded — and is superseded anyway
by the newer run id when a new request was started, so no old-workspace data
is published either way. The identity fence from round 2 is unchanged.

**Outcome regressions (new legs in `page-outcome.test.ts`):**

- *B starts in B layout, resolves after passive* → B keeps its result,
  `loadingVisible` false;
- *B starts in B layout, rejects after passive* → B keeps its error,
  `loadingVisible` false.

## F2 [P2 T-IMP-007] — complete literal pins still escaped

**Finding.** The pin scan still matched only a narrow syntax: a spaced dotenv
value (`EMBEDDING_MODEL = unlisted/police-probe`), an annotated Python pin
(`DEFAULT_MODEL: str = "..."`), an adjacent-literal concatenation, an
`export`ed value, an allowed-prefix-plus-suffix value and an EMPTY value all
passed the gate (POLICE: "Recognized empty pin discarded at 107 is actual gate
weakening").

**Fix — source-aware extraction of the COMPLETE literal value.**

- **Python sources (`.py`)** are parsed with `ast` and the value is read with
  `ast.literal_eval` — the runtime's own semantics, no code is executed. That
  covers annotations, raw strings, triple-quoted strings, parenthesised values
  and ADJACENT string literals, which are **concatenated into one value**
  (Python semantics). A non-literal right-hand side (`os.environ.get(...)`) is
  not a pin — the literal it falls back to is pinned on its own line.
- **dotenv sources** (`.env`, `.env.*`) are read with dotenv semantics: an
  optional `export` keyword, optional whitespace around `=`, an optional
  surrounding pair of quotes, and an inline comment that only starts at a `#`
  preceded by whitespace.
- A file of **unknown type** is read with BOTH interpretations and every pin
  either one finds is validated.
- The **complete** value is validated — never a prefix — and an empty,
  whitespace-only or unapproved value **FAILS** (it is never skipped, never
  truncated).
- The `REJECTED` (China-origin) denylist is **byte-identical** (diff-verified
  against `HEAD`).
- The guard fails closed if `python3` is unavailable.

- per scanned source (3 adapters + `.env.example`): approved pins pass; an

- a 26-case syntax matrix: quoted/bare, whitespace variants, `export`,
