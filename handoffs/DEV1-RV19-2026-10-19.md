# DEV1 handoff — Super RAG review 2026-10-19, workflow-verification lane

TASK: T-RV19-01, T-RV19-02, T-IMP-001 (per `rag-fork-solution/tasks/MICRO-TICKETS-REVIEW-2026-10-19.md`, findings 1, 2 and 4 of `knowledge-os/reviews/2026-10-19-super-rag-review.md`).

CHANGE:

- **T-RV19-01 — verification now evaluates the generated output.**
  `packages/workflow_engine/production_executor.py`:
  - `_evaluate_verification(node, output)` derives the verified claims from the **actual generated `output`**: `answer.prompts.parse_model_output` is used when the model returned JSON claims; plain prose becomes a single claim carrying the generated text.
  - The node's preconfigured `evidence.claims` are **no longer verified as the output**. They are demoted to a *reference set* (chunk ids) that the output claims are checked against, exactly as the review requires ("configured evidence supplies references only").
  - A claim that asserted no reference of its own inherits the configured reference set; a claim that asserted its own references keeps them (so a fabricated reference still fails Stage 11).
  - Candidate citations are built from the output claims and inherit the configured evidence provenance (page/section/span) when the chunk id matches; the `claim_text` is rewritten to the **output** text so Stage 11's coverage check (`_claim_had_citations`) evaluates the text actually produced.
  - Fail-closed paths added: `no_claims_extracted_from_output`, `no_references_provided`.
- **T-RV19-02 — no Stage 12 pass without a semantic verifier.**
  - `ProductionNodeExecutor.__init__` gained a `verifier` parameter (+ `verifier` property): the verifier is resolved through the runtime DI boundary, then from per-node `evidence`.
  - When no verifier resolves, the result is an explicit `verified=False`, `verification_stage="Stage 12 unavailable"`, `verification_reasons=["no_verifier_configured"]` — never the previous fall-through to `verified=True` / `"Stage 11 & 12"`.
- **T-IMP-001 — queued agent runs require a shared durable store.**
  - `docker-compose.yml`: `AGENT_STORE_DB` changed from optional (`${AGENT_STORE_DB:-}`) to **required** (`${AGENT_STORE_DB:?...}`), so a deployment without a shared path cannot start.
  - `apps/api/app/agents/lifecycle_routes.py`: `POST /v1/workspaces/{ws}/agent/runs/queued` refuses admission with **503 `agent_store_not_configured`** when `AGENT_STORE_DB` is unset outside `test`/`dev`/`local`/`""` environments.
  - `apps/api/app/main.py` + `apps/worker/worker/main.py`: log `agent_store_in_memory` (warning) when the store is not configured, instead of silently running process-local.
- **Tests.**
  - `tests/unit/test_workflow_production_executor.py`: evidence `citations` added to the happy paths; `test_production_executor_verification_valid_claims_no_verifier` now asserts the *unavailable* result instead of the misleading success; new `test_production_executor_verification_recording_verifier_receives_output`, new `test_production_executor_verification_checks_output_not_evidence_claim` (output text differs from the configured evidence claim — the verifier must see the output), new `test_production_executor_verification_uses_runtime_verifier` (DI boundary). 12 passed.
  - `tests/unit/test_t_imp_001_agent_store_admission.py` (new): (a) admission refused with 503 `agent_store_not_configured` when no durable store is configured; (b) with a shared store the run is accepted **and claimed by an independent worker process** (different PID, same `AGENT_STORE_DB`) — the direct regression for "parent depth 1 / worker 0". 2 passed.

WHY:
- Finding 1: the executor received the generated `output` and never read it; it verified the node's preconfigured claims and then marked the *independent* LLM output as verified. Reproduced by the reviewer: the provider returned "The moon is made of cheese." while the verifier was called with "The launch budget is 20 dollars.".
- Finding 2: Stage 12 ran only when `evidence['verifier']` was non-null; otherwise execution fell through to `verified: true` / `"Stage 11 & 12"` with zero semantic-verifier calls. Ordinary JSON workflow configuration cannot supply a live verifier object.
- Finding 4: `docker-compose.yml` defaulted `AGENT_STORE_DB` to empty, so the API accepted queued runs into `InMemoryAgentRunQueue` while a separately deployed worker saw depth 0.
