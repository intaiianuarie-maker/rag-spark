CHANGE — the tilde/expansion gap is closed and the path flow is ONE flow
`apps/api/app/agents/lifecycle_routes.py` + `apps/worker/worker/main.py`
(mirrored implementations, pinned by the agreement test):
- `_absolute_path(value)` now validates the **RAW** value
  (`Path(value).is_absolute()`) and NEVER expands it. Previously it
  validated `Path(value).expanduser()` but the **raw string** was used
  afterwards, so `"~/state"` passed validation (expanding to `$HOME/state`)
  and was then handed to the store as the literal relative path `~/state` —
  a directory named `~` relative to the process working directory. Api and
  worker with different CWDs (or different `HOME`) therefore opened two
  different databases while both reported the store as shared.
- Tilde-relative values (`~/state`, `~root/state`) are now refused with the
  same coded reason **`agent_store_path_not_absolute`** (503 admission /
  no worker consumer) in every environment.
- A **raw-absolute path that CONTAINS a tilde component**
  (`/app/dist/~archive/state`) stays valid: there the tilde is an ordinary
  path character, and the store is still shared.
- **One normalized path flow**: the validated raw absolute `Path` objects
  (`db_path`, `root_path`) are used for every subsequent check — containment,
  shadow detection, mount comparison, mount evidence — and the published
  `AgentStoreReadiness.path` is the normalized absolute path, so validation
  and use can no longer diverge. The helper signatures now accept
  `str | Path`.
- Plain-relative refusal and the absolute control are retained unchanged.

WHY:
- The value that was validated was not the value that was used: the
  expansion happened at validation and the raw string at use time. The
  reviewer reproduced the consequence: api 202 + queue depth 1, a fresh
  worker depth 0 / claim None, while both reported `shared=True`.
