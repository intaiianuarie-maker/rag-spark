CHANGE:

**F4b [P2] — a SHADOWED store path is not shared storage**
`apps/api/app/agents/lifecycle_routes.py` + `apps/worker/worker/main.py`
(mirrored implementations, pinned by the agreement test):
- New `root_is_shadowed(root)`. The **intended** shared mount sits at the
  root's own mount point and is NOT shadowing; what shadows the root is a
  *competing* mount:
  1. a known bind mount (the compose source mounts
     `/app/apps/api,/app/apps/worker,/app/packages`, or the ones the
     deployment declares in `AGENT_STORE_SHADOW_MOUNTS`) that lies inside the
     root **or is the root**;
  2. a mount from the process mount table that lies strictly **inside** the
     root (a nested mount covers the volume's subtree there).
  A mount that is an **ancestor** of the root is the normal filesystem and
  never shadows it; the mount **at** the root is the intended volume.
- A shadowed root is refused in staging/production:
  `admit=False`, `shared=False`, `reason="agent_store_root_shadowed"` →
  **503 admission refusal** in the API and **no worker consumer** in the
  worker.
- `_mount_points()` now reads the mount table from
  `AGENT_STORE_MOUNTINFO` (default `/proc/self/mountinfo`), so the
  definitions can be probed with a synthetic mountinfo file — no container
  required.
- `docker-compose.yml` publishes `AGENT_STORE_SHADOW_MOUNTS`.
