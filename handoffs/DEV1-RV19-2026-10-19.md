CHANGE:

**F1 [P1] T-RV19-01 — coverage is EXACT, not casefolded**
`packages/workflow_engine/production_executor.py`:
- `_text_covered()` no longer casefolds or collapses whitespace. A published
  answer is covered only when it is **byte-identical** to an already-verified
  claim. "The device draws 20 mW." and "The device draws 20 MW." are
  different claims, and so are case-sensitive identifiers
  (`AcmeCorp` vs `acmecorp`).
- Consequence: an answer that differs in any way is no longer treated as
  covered — it joins the verification set as its own claim, so the semantic
  verifier is asked about the *published* text. The reviewer's probe (a
  verifier supporting only the exact mW claim) now yields
  `verified=false`, and the altered answer is never published as verified.

**F4b [P1] T-IMP-001 — the shared volume follows the resolved root**
- `docker-compose.yml`: the `agentdata` named volume is now mounted at the
  **RESOLVED** shared root in BOTH services
  (`- agentdata:${AGENT_STORE_SHARED_ROOT:-/app/.agent}`), and
  `AGENT_STORE_DB` defaults inside that root
  (`${AGENT_STORE_DB:-${AGENT_STORE_SHARED_ROOT:-/app/.agent}/agent.db}`).
  The reviewerer's reproduction (`AGENT_STORE_SHARED_ROOT=/tmp/review-private`)
  now renders the mount AT `/tmp/review-private` in api and worker, so the
  admitted database is on the same named volume in both services.
- New env var `AGENT_STORE_SHARED_MOUNT` publishes the actual mount target.
  The application refuses to report the store as shared when the resolved root
  is not that mount (`agent_store_root_not_mounted`): the root and the mount
  are compared at runtime in both the API
  (`apps/api/app/agents/lifecycle_routes.py`) and the worker
  (`apps/worker/worker/main.py`), so a hand-built deployment that overrides
  the root without moving the volume is refused (503 / no worker consumer).
- `.env.example` documents `AGENT_STORE_SHARED_MOUNT`.

WHY:
- F1: casefolded coverage was treated as semantic equivalence, so a verifier
  that only supported the exact "20 mW" claim never saw the published
  "20 MW" answer, and the altered answer was published with
  `verified=true` / `"Stage 11 & 12"`. Units and identifiers are
  case-sensitive; coverage must be exact.
- F4b: a configured shared root could disagree with the ACTUAL shared mount:
  `docker compose config` succeeded with
  `AGENT_STORE_SHARED_ROOT=/tmp/review-private` while `agentdata` was
  mounted only at `/app/.agent`, so the admitted database sat in separate
  container filesystems while both readiness checks reported
  `shared=true`.
